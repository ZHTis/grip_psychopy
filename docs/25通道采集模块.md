# RX-G0505M：25 通道独立采集模块

本模块只接收、校验、预览和保存设备原始上报值。左右手各保留 25 通道，不求和、不归一化，也不决定哪个通道控制游戏。原有 UNO 读取保持原状；新增的 [左手加权游戏模式](左手加权调参与游戏.md) 可通过独立入口把这些数据用于飞行及实时调权。

## 最快开始

在项目根目录执行（Mac 使用现有包装脚本，自动处理 PsychoPy Standalone 的 Python 路径）：

```bash
# 无设备测试；模拟双手，每手 25 通道，运行 5 秒
bash run_python.sh record_multichannel_grip.py --simulate --seconds 5

# 查看串口，找到配套 USB 接收器
bash run_python.sh record_multichannel_grip.py --list-ports

# 真机采集：替换为上一步的实际串口，Ctrl+C 结束
bash run_python.sh record_multichannel_grip.py --port /dev/cu.usbserial-130
```

Windows 在已配置的 PsychoPy/Python 环境中：

```powershell
.\run_python.bat record_multichannel_grip.py --list-ports
.\run_python.bat record_multichannel_grip.py --port COM6
```

`/dev/cu.usbserial-130` 和 `COM6` 只是示例端口。串口依赖 `pyserial`，已列在项目 `requirements.txt` 中。先关闭厂家软件或其他串口监视程序，避免争用同一接收器。

常用参数：

| 参数 | 含义 |
|---|---|
| `--seconds 60` | 收到所需手的有效数据后再运行 60 秒；默认 0，持续到 Ctrl+C |
| `--hand left` / `right` / `both` | 要求指定手有新数据；默认 `any`，任一手即可 |
| `--stale-seconds 2` | 所需手超过该时间无新帧则结束并记录错误；默认 2 秒 |
| `--timeout 5` | 启动等待有效数据的时间；默认 5 秒 |
| `--serial-number 实际序列号` | 按 USB 接收器的唯一序列号查找端口，与 `--port` 二选一 |
| `--output data/multichannel` | 输出目录；相对路径从项目根目录计算，不受当前终端目录影响 |
| `--simulate` | 生成明确标记的测试数据，不打开设备、不发送串口指令 |

`--hand` 控制启动等待和过期检查，**不会过滤掉另一只手的数据**；只要收到有效帧，全部保存。默认 `any` 下，一只手断流而另一只仍在线时继续记录，预览将缺失手标为 `no fresh data`。需要双手完整性时明确使用 `--hand both`。

## 协议与输出

依据仓库内 [厂家手册](G0505M_manual.pdf) 第 19–20 页实现：115200 baud、8N1、无流控，固定 53 字节二进制帧。帧头 `40`，手标识 `31`（左）或 `32`（右），随后 25 个大端无符号 16 位整数，最后为前 52 字节之和的低 8 位。

模块支持半帧、多帧、左右手交错和错位后的重新同步。校验不通过的候选帧不会作为测量样本发布，原始字节仍保存。加和校验不能发现所有传输错误；`checksum_errors` 是校验失败候选数，不是准确的丢帧数。

终端每秒预览一次全部 25 通道；后台按设备实际到达速率记录，不根据显示频率抽样或补帧。模块不改变采集器配置，也不发送旧 UNO 的 `Q/S` 时钟同步消息。

默认每次采集新建 `data/multichannel/日期时间_随机编号/`：

| 文件 | 内容 |
|---|---|
| `grip_multichannel.csv` | 每行一个有效帧；含 `hand`、接收时间和 `point_01_g` 到 `point_25_g` |
| `grip_multichannel_bytes.csv` | 每次串口读取的原始十六进制字节及接收时间，可离线复查异常帧 |
| `grip_multichannel_summary.csv` | 采集结束统计；左右手计数保存在 `payload_json.frames_by_hand` |
| `diagnostics.csv` | 校验重同步、断流、读取错误、退出时残留半帧等信息，细节在 `payload_json` |
| `events.csv` | 本地 ready/end/abort 事件 |
| `metadata.json` | 设备、25 通道顺序、单位说明、模拟标志及结束状态 |
| `session.sqlite3` | 原始记录数据库，含完整帧和全部原始字节 |

共用记录器还会创建旧任务用的空 CSV，它们在本次独立采集中没有数据。每 0.25 秒提交数据库，正常结束/Ctrl+C/已处理的采集错误会导出 CSV。强制杀进程或断电可能丢失最后未提交事务；可用 `gripflight.recording.export_existing(session_directory)` 从数据库重新导出。

数值单位 `g` 沿用厂家上报定义，没有进行额外计量标定或力学换算。数组第 0 项永远是通道 1，第 24 项永远是通道 25。该协议没有设备采样时间和序号：

- `t_host_s` / 样本的 `t`：相对于同一个 Recorder 起点的电脑单调时钟秒数。
- `host_unix_s`：电脑收到字节块后的 Unix 时间戳，便于查看日期时间；不是稳定间隔时钟。
- 一次串口读取中的多个完整帧共享该块接收时间；跨块帧使用包含帧尾的那一块时间。
- `received_index`：本次采集在电脑端给有效帧依次编号，跨左右手递增；**不是设备序号，也不能用于推断丢帧**。
- `device_timed=false`、`device_sequence` 和 `device_micros` 留空。不能据接收时间宣称精确的采样时间或脑电同步精度。

## 在 PsychoPy 任务中使用

实现文件：[gripflight/multichannel.py](../gripflight/multichannel.py)。模块本身不依赖 PsychoPy，后台线程不会等待屏幕刷新。使用现有任务的同一个 Recorder，可让本地事件和接收时间处于同一主机时基；这仍不等于设备采样时钟同步。

```python
from gripflight.multichannel import MultiChannelGripReader

# recorder 是已创建的严格 Recorder；port 是配套 USB 接收器端口。
reader = MultiChannelGripReader(recorder, port=port, ordered=True).start()
try:
    reader.wait_ready(timeout=5, hand='left')
    while task_is_running:
        # 每个显示帧取出这段时间到达的全部样本。
        for sample in reader.take_samples():
            hand = sample['hand']        # 'left' / 'right'
            values = sample['values_g']  # 恰好 25 个整数，尚未整合
            # 在这里交给今后的任务映射；原始样本已经由后台线程保存。

        # 如任务依赖左手输入，单独检查左手是否仍有新数据。
        reader.latest('left', max_age=2.0)
        # 按任务需要绘制画面、处理按键、win.flip()。
        # 任务主线程还应定期 recorder.flush()。
finally:
    reader.close()  # 必须先停止采集线程，再关闭 recorder。
```

以上是接入片段，不是独立可运行脚本；完整独立入口为 [record_multichannel_grip.py](../record_multichannel_grip.py)。

只需预览最近值时，使用默认 `ordered=False`，再调用 `latest('left')` 或 `latest('right')`；所有帧仍会被后台保存，不会只记录预览值。`latest()` 在缺失、过期或读取失败时抛出异常，不会将旧值或零伪装成新测量。

使用 `ordered=True` 时必须持续调用 `take_samples()`。任务队列默认上限 4096 帧，积压溢出会显式报错；当前已读字节块内的完整帧仍先存入数据库。这里没有“缺样沿用上一值”的游戏降级逻辑，后续由任务设计决定。

### 与 handy 实际读取案例的对照

已于 2026-10-14 对照同机 `handy/server.py` 的 `Parser` 与串口读取流程：115200 / 8N1 / 无流控、53 字节帧、左右手标识、25 个大端整数、加和校验及校验失败后逐字节重新同步均一致。新模块通过 pyserial 支持 Mac/Windows，不依赖 handy 服务运行。

接口对应关系：

| handy | 本项目采集模块 |
|---|---|
| `hand="1"` / `"2"` | `hand="left"` / `"right"`；另保留整数 `hand_code=1/2` |
| `values[0:25]` | `values_g[0:25]`，通道顺序和值不变 |
| `seq` | `received_index`，两者均为电脑端编号，不是设备采样序号 |
| `time` | `host_unix_s`，均为主机时间；本模块另保留 Recorder 单调时钟 `t` |

handy 在解析每个帧时调用主机时钟；本模块在串口 read 返回后取时，同一字节块中的帧共享接收时间。因此只要求帧内容和顺序一致，不把微小的主机时间差当成设备采样间隔。

离线验证使用 handy 现有 CSV 的 79 行记录，每行 25 值，重建协议帧后按 30 种随机分包方式同时送入两套解析器；另用 200 个随机左右手帧加入噪声、错误校验及末尾半帧，按 30 种分包方式比较。全部帧内容、顺序和校验失败计数一致。CSV 没有保留原始串口字节，这项验证是数据回放与解析兼容性验证，不代替新模块的真机串口测试。

使用本模块前请先在 handy 中点击“断开”，或停止它的服务；仅关闭网页不会释放它持有的串口。不要让两个程序同时读取同一接收器。
