# 左手 25 通道加权升力与实时调参

新模式使用 RX-G0505M 左手 25 个测点生成飞行输入。原来的 UNO 模式仍使用 `launch_hardware.command` / `config.json`；新模式有独立的启动脚本、配置和权重文件。

## 启动

Mac，在项目目录运行：

```bash
# 没有设备：体验游戏和调参面板
bash launch_multichannel.command --simulate

# 有接收器：自动寻找唯一的 CH340 接收器
bash launch_multichannel.command

# 无法自动确定时，查看并指定实际串口
bash run_python.sh run_task.py --list-ports
bash launch_multichannel.command --grip-port /dev/cu.usbserial-实际编号
```

Windows（PsychoPy Standalone 或已安装依赖的 Python）：

```powershell
.\launch_multichannel.bat --simulate
.\launch_multichannel.bat --grip-port COM6
```

示例串口应替换为当前设备端口。也可在 `config_multichannel.json` 的 `multichannel.port` 固定填写端口，或在 `multichannel.serial_number` 填接收器实际序列号。自动识别只适用于电脑上唯一一个 CH340；CH340 标识本身不能证明它是握力接收器，多设备时应明确指定。先在 handy 中断开接收器或停止服务，释放串口。

默认关闭硬件打标，本地事件照常保存。需要打标时加 `--enable-markers`，使用该配置内原有的打标板序列号。新接收器不沿用 UNO 握力板的串口或身份配置，也不发送 UNO 的同步指令。

## 一边玩一边调

当前默认直接试玩：25 通道模式的 `calibration.enabled=false`，跳过零点和最大握力标定。启动后会打开 PsychoPy 游戏窗口，并请求浏览器另开一个实时调参窗口，终端也会打印面板链接。默认窗口显示，便于同屏放置游戏和面板；若浏览器未自动打开，可复制终端链接到浏览器。

1. 接收器收到左手数据后，直接进入游戏的 Ready / Prepare / 飞行流程，无需先握紧标定或按空格确认。调参窗口显示 25 点的力、权重和实际占比，启动即可修改。
2. 面板显示全部 25 个通道的原始值、权重、实际占比及去零后的加权贡献。滑块或数字修改约 0.25 秒后生效，也可将某点设为 0 来排除该点。
3. `升力系数`对应新模式的 LIFTGAIN；`参考倍率`越大，相同握力输入产生的升力越小。游戏原有平滑参数仍生效。
4. 单屏调节时可点“暂停游戏”；飞行进度停止，后台原始数据仍持续记录。改好后点“继续游戏”。校准过程中不支持暂停。
5. “保存为下次默认”写入 `left_hand_weights.json`；没有点击保存的调节仍归档于本次数据，但下次启动不会沿用。“恢复图片权重”只重置各点权重，保留升力系数和参考倍率。
6. Esc（游戏窗口）或“结束任务”（面板）停止并保存本次记录。任务结束后面板不再可调。

模拟模式无需串口，同样默认跳过校准。进入游戏后，可使用面板的“模拟用力”滑块持续控制，也可在游戏窗口按住鼠标左键施力。模拟数据均有明确标识。

双屏可在 `config_multichannel.json` 设置 `display.screen` 为外接屏对应序号（通常为 1），然后：

```bash
bash launch_multichannel.command --fullscreen
```

在另一块屏幕放置调参面板。`--windowed` 则使用主屏窗口。不能同时运行两个串口读取程序连接同一接收器。

## 游戏窗口右侧的实时五指图

25 通道模式在 PsychoPy 窗口右侧显示左手五指压力图，覆盖零点、握紧、休息、校准完成等待及游戏阶段。采用 handy 监视器的五指轮廓、原始通道坐标和蓝绿配色，对应说明书第 6 页。每个点上方是通道号，下方是设备上报原始值（g），不是扣零或加权后的数值；压力越大，颜色越亮。

图形与游戏使用同一采集线程，不启动 handy 服务、不另开串口。即使暂停游戏，压力图也继续更新。无需另外运行 `handy/启动监视器.command`。

`config_multichannel.json` 的新显示参数：

| 参数 | 默认值 | 用途 |
|---|---:|---|
| `display.size` | `[1200, 700]` | 窗口尺寸，为右侧图留空间 |
| `display.pressure_panel_fraction` | `0.38` | 右侧占窗口宽度的比例，允许 0.25–0.6 |
| `display.pressure_color_max_g` | `5000` | 颜色饱和上限，与 handy 默认一致；超过上限仍显示实际数字，不改变数据或升力 |
| `calibration.rest_s` | `6.0` | 两次握紧之间的休息，从原 30 秒缩短为 6 秒 |

零点 5 秒、每次握紧 1 秒和最少有效样本数保持原值。原 UNO 任务仍使用完整窗口和原有 30 秒休息。五指图代码为 `gripflight/pressure_display.py`，静态轮廓为 `assets/left_hand_map.svg`；移动项目时一并复制。

## 图片权重如何分配到测点

按用户提供的左手图片取七个区域比例，再按已确认的方式在区域内平均分配。下表通道编号从 1 开始，与设备原始 25 通道顺序一致。

| 区域 | 区域初始权重 | 测点 | 每点初始权重 |
|---|---:|---|---:|
| 拇指 | 20% | 1、6、11 | 6.666667 |
| 食指 | 20% | 2、7、12、17 | 5 |
| 中指 | 14% | 3、8、13、18 | 3.5 |
| 无名指 | 13% | 4、9、14、19 | 3.25 |
| 小指 | 10% | 5、10、15、20 | 2.5 |
| 大鱼际 | 20% | 16、21、22 | 6.666667 |
| 小鱼际 | 3% | 23、24、25 | 1 |

区域内的分配总和等于该区域权重，不因测点更多而自动获得更多权重。上述**区域与点号的对应是根据厂家手册第 6 页位置图制定的项目初始分组**，尤其掌部的区域边界需要按实际贴片位置核对，不是厂家提供的七区域分类。逐点按压并观察面板，可确认编号对应的位置。若实际位置不同，可调整各通道权重；区域分组定义在 `gripflight/weights.py` 的 `REGIONS`。

这些比例是本次游戏的初始控制参数，不能视为适用于每位参与者的生理标准。

## 升力计算

对第 i 点，设原始值为 `xᵢ`，本次零点为 `bᵢ`，界面填写的非负权重为 `aᵢ`：

```text
wᵢ = aᵢ / Σaᵢ                       # 自动归一化，权重不必相加等于 100
sᵢ = max(0, xᵢ - bᵢ)                # 逐点扣除零点
S  = Σ(wᵢ × sᵢ)                     # 整体用力指标
rᵢ = max(三次握紧中该点峰值) - bᵢ   # 负值归零
R  = 参考倍率 × Σ(wᵢ × rᵢ)
u  = min(1, S/R)
升力 = LIFTGAIN × 原游戏平滑后的 u
```

零点采用静息段各点中位数。三个握紧窗口中全部有效左手数据用于取峰值，各点峰值不要求出现在同一时刻；因此 `R` 是组合参考，不等于某次实际同时测得的总力。每次握紧的加权峰值须超过最小范围及零点噪声阈值。

调整权重后，会用本次保存的逐点校准范围重新计算 `R`。因此权重改变的是各测点对整体控制的相对影响；若所有点相对于各自参考范围始终以相同比例施力，仅改变权重可能不会改变归一化输入。整体力度难易可调“参考倍率”或“升力系数”。

全部权重为 0、负数或非有限数会被拒绝；如果所选测点在校准中全部没有响应，也会拒绝这一修改，并保留上一组有效参数。

设备上报单位沿用厂家 `g`，`S` 是加权读数，不是经整体计量标定的总握力。默认权重文件里的 `lift_gain` 是新模式的起始值，优先于 `config_multichannel.json` 的 `task.lift_gain`；如设 `calibration.lift_mode=target_fraction`，则按原任务约定用 `gravity/target_fraction` 作为起始升力系数。之后可从面板修改。

当前已关闭校准：每点零点使用 0、参考范围使用 1000 g，加权后除以临时参考范围，再乘升力系数。面板明确显示“未标定”，归档的校准状态为 `disabled`。参考倍率调小，按压更容易产生升力；调权重会改变各点占比，修改后约 0.25 秒生效。此参考不是测得的最大握力。

以后恢复标定时，把 `config_multichannel.json` 的 `calibration.enabled` 改回 `true`：恢复 5 秒零点、三次各 1 秒握紧、两段各 6 秒休息，以及校准完成按空格进入游戏。原 UNO 模式的校准设置没有改变。`--headless` 仍是跳过校准的快速逻辑测试。

## 数据与时间

每次运行保存到 `data/weighted/日期时间_编号/`：

- `grip_multichannel.csv`：收到的全部有效原始帧，保留左右手全部通道；控制输入仅取左手。
- `grip_multichannel_bytes.csv`：原始串口字节，用于复查解析。
- `weight_updates.csv`：每次生效参数的版本、时间、原因；`payload_json` 含完整权重、零点、参考范围、升力系数和倍率。初始、校准、调参都会记录；“保存默认”记录同一参数版本的保存事件。
- `task.csv`：每个物理步的 `weight_revision`、`weighted_g`、`reference_g`、`lift_gain`、`applied_lift`，以及所用原始帧的 `grip_sample_id`、数据年龄、`input_reused` 等。通过 `grip_sample_id` 对应原始记录的 `id`，再按参数版本重建计算。
- `experiment_setup.json`：三次握紧的全部校准样本及各点峰值、零点、最终参数、原始/实际配置和地图内容。
- `events.csv` / `session.sqlite3`：事件、暂停恢复记录及完整记录数据库。

物理步采用独立的主机 60 Hz 时钟；设备数据按真实到达速率保存。两帧之间控制沿用最近一帧，并通过 `input_reused` 标识重复使用，不伪造设备样本。默认左手超过 2 秒无新帧则停止并保存错误，右手仍有数据不能替代左手。新加权模式出现记录失败会停止；这与旧 UNO 模式的容错行为不同。

`--headless --simulate` 仅快速逻辑测试，跳过真实时间等待及校准，不能用于评估时序。设备协议无设备采样序号/时间，接收时刻仍只是电脑时间。

## 文件与验证

- `gripflight/multichannel.py`：原始串口读取，仍可独立使用。
- `gripflight/weights.py`：区域初值、零点、加权映射、参数版本。
- `gripflight/weighted_task.py`：新模式校准及游戏循环。
- `gripflight/weight_panel.py` / `weight_panel.html`：只监听本机的调参面板；不占用第二个串口。
- `config_multichannel.json` / `left_hand_weights.json`：新设备任务配置及默认权重。

自动测试覆盖初值分配、去零与参考重算、实时改权对飞行的影响、无效修改拒绝、并发版本冲突、保存/重载、游戏时钟暂停、三次校准和中断、面板接口及数据导出。实际接收器的通道位置、响应方向和连续使用效果，仍须连接设备逐点检查。
